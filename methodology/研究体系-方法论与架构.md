# 研究体系：方法论、底层架构与流程图（2026-11-19）

> 本文档把"中美 AI 对比"研究的方法论、系统架构与数据通道固化下来：**为什么这样设计、数据怎么来、证据怎么管、判断怎么下、版本怎么迭代**。
> 架构图：`reports/charts/研究体系架构-20261119.png`（从数据到判断的六环节与反馈回路）。

## 一、方法论总览：六环节

1. **数据源（一手）**：巨潮资讯网（A 股公告/定期报告）、SEC EDGAR（10-K/10-Q/20-F/companyfacts）、中国海关总署（进出口数据）、公司业绩公告（腾讯/微软/谷歌/亚马逊/Meta 等）。
2. **抓取与清洗**：按代码/CIK 查询公告 → 下载 PDF → pypdf 解析 → 关键数字提取 → 去重/纠错 → 落库；跨市场数字（TWD→USD 等）统一换算。
3. **证据库（可回溯）**：`key_claims.jsonl`（逐条主张 + 数值 + 来源 + 定位 + 日期 + 证据等级）、`falsification_ledger.jsonl`（证伪条件 + 证据 + 状态）、财务底表 JSON。
4. **分析框架**：L1–L5 分层 × 美国 12 家 × A 股 23 家 × 跨市场比率；A 股另设 AI 纯度/风险分四象限。
5. **判断与评分**：基于证据形成判断，标注置信度与可证伪条件；C1–C3 为核心假设。
6. **产出与迭代**：看板、交付版、公开版、图表、数据附件；季报/公告触发反馈回路 → 回原文 → 更新证据 → 状态变更 → 新版本。

## 二、底层架构：三层 + 一条固定通道

**数据层**（可回溯）
- 原文 PDF：`data/` 下的结构化数据（见 data/README.md）；
- 结构化：`data/key_claims.jsonl`（197 条）、`data/falsification_ledger.jsonl`（48 条）、`data/us_sec_expand.json`、`data/us_capex_qtr.json`；
- 校验：`pipeline.py check --schema key_claims|ledger`，全部 PASS 才允许引用。

**证据层**（分级）
- L1 一手原文：公告/财报/SEC/海关；
- L2 由原文计算或扫描：必须回原文核对；
- L3 媒体/研报线索：只作方向，不作定量结论。
- 每条 claim 记录 `id / claim / value / unit / source / locator / retrieved_at / confidence / 口径`。

**分析与判断层**
- L1–L5 分层：每层有同质商业模式与可比指标；
- 样本：美国 12 家（云/芯片/制造/软件/网络）；A 股 23 家（公告可核、原文可得的 AI/算力公司）；
- 指标：营收增速、毛利率、OCF、capex/OCF、负债率/有息负债、云或算力收入占比；
- 评分：AI 纯度（0–10）+ 风险分（0–9）→ 四象限；
- 证伪：先写推翻条件，再跟踪证据（C1/C2/C3）。

**产出层**
- 看板（23 家状态）、交付版报告、公开版报告、图表、数据附件；
- 双版本：内部版（带路径/数据）与公开版（脱敏/引用/免责）。

**固定数据通道（固化技能）**
```
源（巨潮/SEC/海关）→ 查询（代码/CIK）→ 下载 PDF → 解析（pypdf）
→ 清洗（数字规范化/去重/纠错）→ 入库（key_claims/ledger）
→ 校验（schema PASS）→ 使用（报告/图表）
```
- 工具脚本：`scripts/fetch_cninfo.py`、`scripts/fetch_sec_companyfacts.py`、`scripts/validate_claims.py`；
- 失败处理：标题误匹配（提示性公告/摘要）→ 精确标题重抓；版式差异 → 换关键词/分页定位；数字异常 → 回原文人工核对。

## 三、为什么这样设计（设计理由）

1. **分层而非总分**：AI 产业链价值分布不均（芯片毛利 70%+、云 50%–60%、集成 15%–25%），不分层会把"卖铲子"与"包工头"混谈；
2. **比率而非绝对额**：中美币种/财年/会计口径不同，只比较结构与比率；
3. **证据分级**：中美披露质量差异大，L3 只作方向，定量必须 L1；
4. **样本可核**：A 股 23 家不是"全部 AI 公司"，而是"公告可核、原文可得的样本"，存在样本偏差并明确承认；
5. **先证伪后判断**：避免"叙事先行"，让结论可被检验；
6. **双版本**：内部保留路径与数据，公开版脱敏、引用、免责。

## 四、判断与证伪协议

- 每条核心判断记录：**判断内容 / 证据基础 / 置信度（高/中高/中/低）/ 可证伪条件**；
- C1：AI 收入增速 > capex 增速（确认条件）→ 当前 partial；
- C2：AI 应用高毛利可维持（证伪：毛利率连续两季下滑 >3pp 或 <40%）→ A 股偏证伪；
- C3：capex 可由 OCF 支撑（证伪：capex/OCF>100% 或 FCF 连续两季为负）→ 分化；
- 状态变更必须写入证伪账本（追加证据 + 状态），不允许"悄悄改叙事"。

## 五、质量门（每次出报告前）

1. `pipeline check`：key_claims / ledger 全部 PASS；
2. A 股原文齐全：Q3 23/23、H1 23/23（缺则标注）；
3. 跨市场数字：单位/币种/财年标注；
4. 公开版：脱敏扫描（路径/邮箱/手机号/wxid/姓名/token）、引用清单、免责声明；
5. 版本记录：改动写入记忆仓库日志与项目状态。

## 六、迭代协议

- **触发**：季报/年报/重大公告（美国 Q4 财报、A 股 2026 年报与 2027 一季报）；
- **动作**：回原文 → 更新证据库 → 重算比率 → 检查证伪条件 → 记录状态变更 → 升版本号；
- **节奏**：A 股公告哨兵每周一 09:30；证伪账本随报告更新；公开版随内部版同步。

## 七、边界（设计的一部分）

- 不预测股价、不做估值与择时；
- 不评技术路线（模型/芯片路线变化太快）；
- 不覆盖未上市公司（OpenAI/Anthropic/字节 AI 等）——会低估美国模型层与中国应用层；
- 结论是方向性的，不是精确的；数据缺陷需持续修补。
